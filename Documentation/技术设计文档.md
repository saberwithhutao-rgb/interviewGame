# 技术设计文档 —— 《面试项目》（Unity 射击生存类游戏）

> 本文档基于项目代码目录结构分析，涵盖核心架构、模块设计、数据驱动方案及关键实现思路。项目采用 Unity 引擎，支持局域网/Steam 联机，融合了技能、Buff、状态、关卡、经验值等典型 RPG 元素。

---

## 1. 项目概述

**项目名称**：interview project  
**技术栈**：Unity（URP/HDRP 不限）、C#、Unity Netcode（含 Steam 联机）、ScriptableObject  
**核心玩法**：第三人称射击生存，玩家通过击杀敌人获取经验，升级后选择 Buff 或技能，面对不断增强的敌人，支持多人合作。  
**代码规模**：约 150+ 脚本文件，涵盖战斗、UI、网络、数据、管理等模块。

---

## 2. 整体架构

### 2.1 分层结构

- **数据层（Data Layer）**：以 `ScriptableObject` 为主，存放所有静态配置（Buff/技能/状态/关卡数值），位于 `Assets/ScriptableObjects`。
- **逻辑层（Logic Layer）**：各类 Manager 和 System 类，负责运行时逻辑（玩家、敌人、战斗、网络、UI 等），位于 `Assets/Scenes/Script`。
- **表现层（Presentation Layer）**：UI 面板、特效、动画、音效等，通过事件与逻辑层解耦。

### 2.2 模块划分
┌───────────────────────────────────────────────────────────┐
│ Game Manager 层                                           │
│ GameEvents, LevelManager, ScoreManager, SaveManager       │
├──────────┬──────────┬──────────┬──────────┬───────────────┤
│ 玩家模块  │ 敌人模块   │ 战斗模块  │ 技能/Buff │ 网络模块       │
│ Player*  │ Enemy*   │ Bullet   │ Status   │ Netcode       │
│ Stats    │ Spawner  │ Damage   │ Manager  │ Steam         │
├──────────┴──────────┴──────────┴──────────┴───────────────┤
│ UI 模块 (UIManager)                                        │
│ HUD, 菜单, 伤害数字, 聊天, 设置等                             │
├───────────────────────────────────────────────────────────┤
│ 数据配置层 (ScriptableObject)                               │
│ BuffData, SkillData, StatusData, LevelData                │
└───────────────────────────────────────────────────────────┘

## 3. 核心模块详解

### 3.1 游戏全局管理

| 类 | 职责 |
|----|------|
| `GameEvents` | 全局事件中心（如玩家死亡、击杀、升级等），解耦模块通信。 |
| `LevelManager` | 管理关卡切换、关卡数据（`LevelData`）加载，控制波次生成。 |
| `ScoreManager` | 记录玩家得分、击杀数，并更新 UI。 |
| `SaveManager` | 存档/读档，使用 `SaveDataModels` 保存玩家进度、设置等。 |
| `AudioManager` | 管理音效和背景音乐，可能使用对象池控制音频源。 |

### 3.2 玩家模块

| 类 | 职责 |
|----|------|
| `PlayerControl` | 玩家输入控制（移动、瞄准、射击），依赖 `MouseController` 和 `ThirdPersonCamera`。 |
| `PlayerStats` | 玩家数值（生命、护甲、移速、攻击力等），支持动态修改（Buff/技能影响）。 |
| `PlayerHealth` | 生命值管理，触发死亡事件，显示血条（`PlayerHealthbar`）。 |
| `PlayerComponentEnabler` | 针对网络联机，控制客户端/服务器端的组件启用。 |
| `AnimationEventReceiver` | 接收动画事件（如射击、装填），触发对应逻辑。 |
| `PlayerFootstep` | 脚步声效播放。 |
| `PlayerTracker` | 用于追踪玩家位置，供敌人 AI 使用。 |

### 3.3 敌人模块

敌人采用继承层次：
- `EnemyStats`（基类）→ `ZombieStats`、`FreeKnightStats`、`SkeletonWarriorStats` 等
- `Enemy`（基类）→ `Zombie`、`FreeKnight`、`SkeletonWarrior` 等

每个敌人有对应的 Stats 子类，在 Inspector 中配置不同数值，实现数据与行为分离。

- `EnemySpawner`：按关卡配置生成敌人，由 `LevelManager` 触发。
- `EnemyHealthBar`：敌人头顶血条 UI。
- `EnemyBuffManager`：全局敌人 Buff（难度缩放）。
- `EnemyStats`：基础数值，子类可覆盖（如 `ZombieStats` 设置僵尸专属数值）。

### 3.4 战斗系统

#### 3.4.1 伤害体系
- `IDamageable` 接口：所有可受伤害的对象（玩家、敌人、可破坏物）实现该接口。
- `DamageSystem`：处理伤害计算（考虑防御、伤害类型、暴击等），通过 `DamageType` 枚举区分物理/魔法等。
- `Bullet`：子弹实体，命中后调用 `IDamageable.TakeDamage`，并支持对象池（`BulletPoolManager`）。
- `Gun`：枪械逻辑，射击、装填、后坐力，绑定 `GunPoint` 和动态准星 `DynamicCrosshair`。

#### 3.4.2 Buff 系统
- 数据：`BuffData`（ScriptableObject）定义属性加成（伤害、生命、移速、装填速度）。
- 效果：`BuffEffect` 是普通 C# 类，派生类（如 `DamageUpEffect`）实现具体逻辑。
- 管理：`BuffManager` 维护当前激活的 Buff，通过 `BuffSelector` 提供 UI 选择（升级三选一）。
- 应用方式：`BuffData` 通过 `BuffEffect` 修改 `PlayerStats` 的倍率字段。

#### 3.4.3 技能系统
- 分为**主动技能**和**被动技能**：
  - 主动：`SkillData` 定义消耗、冷却，`SkillEffect` 实现具体效果（治疗、伤害、状态施加等）。
  - 被动：`IPassiveEffect` 接口，`PassiveSkillManager` 负责触发条件（如击杀、受伤）。
- 技能解锁：`SkillUnlockManager` 控制技能获取，`SkillSelectionPanel` 提供选择界面。
- 数据库：`SkillDatabase` 持有所有技能配置。

#### 3.4.4 状态（Status）系统
- 用于持续性负面/正面效果（如中毒、灼烧）。
- `StatusData` 定义持续时间和 tick 间隔。
- `StatusEffect`（如 `PoisonTickEffect`）在 `StatusManager` 中每帧更新，造成持续伤害或治疗。
- 与 Buff 的区别：Buff 通常永久或持续固定时间直接修改属性，Status 是周期触发效果。

### 3.5 经验与升级
- `ExperienceManager`：管理经验值转移，只在服务器执行。
- `IExperienceSource`：**被击杀者**（如敌人）实现该接口提供基础经验值。
- `IExperienceReceiver`：**击杀者**（如玩家）实现该接口接收经验。
- 经验转移时，`ExperienceManager` 计算实际经验（等级差衰减等），调用 `receiver.AddExperience()`。

### 3.6 网络模块
- 基于 Unity Netcode，支持 Steam 联机（`SteamManager`）。
- `LobbyNetworkStarter` / `AutoHostStarter`：启动主机或客户端。
- `NetworkUI`：显示连接状态、房间信息。
- `ClientNetworkTransform` 和 `ClientNetworkAnimator`：实现网络同步（来自 Unity.Netcode.Components）。
- `DestroyNetworkManagerOnLoad`：防止重复加载网络管理器。
- **注意**：当前未实现主机迁移，游戏依赖 Host 在线。

### 3.7 UI 系统
- `UIManager`：统一管理面板显示（主菜单、死亡界面、胜利界面、设置等）。
- 子面板：`DeathMenu`、`WinMenu`、`MainMenu`、`FullScreenModal`、`ChatManager`。
- 游戏内 HUD：`GunPanel`（显示弹药）、`ScoreUI`、`EndlessKillUI`、`DamagePopup`（伤害数字）。
- 设置：`SettingsManager` 控制音量、灵敏度，配合 `VolumeSlider` 和 `SensitivitySlider` 实现实时调整。

## 4. 数据配置设计（ScriptableObject）

所有静态数据以 `.asset` 文件存放在 `ScriptableObjects` 目录，便于策划调参。

| 目录 | 内容 |
|------|------|
| `Buffs/BuffDatas` | 各 Buff 属性加成数值（如 `DamageUp01.asset`）。 |
| `Buffs/BuffEffects` | Buff 效果实例（关联对应的 `BuffEffect` 脚本）。 |
| `Levels` | 关卡数据（`Level_XX.asset`），包含敌人波次、生成间隔、难度系数等。 |
| `Skills/SkillData` | 每个技能的具体参数（消耗、冷却、描述、图标等）。 |
| `Skills/SkillEffect` | 技能效果资产（如 `HealEffect.asset`）绑定对应 C# 类。 |
| `Skills/SkillDatabase.asset` | 技能库总表。 |
| `Status/StatusData` | 状态配置（持续时间、伤害间隔等）。 |
| `Status/StatusEffect` | 状态效果资产。 |

**设计优势**：
- 数据和逻辑分离，修改配置无需重新编译。
- 支持离线调整（非运行时热更新）。
- 支持运行时动态加载/卸载（如关卡切换）。

## 5. 关键流程

### 5.1 战斗流程
1. 玩家瞄准敌人并射击 → `Gun` 生成 `Bullet`（从对象池）。
2. `Bullet` 飞行碰撞后调用 `IDamageable.TakeDamage(damage, damageType, source)`。
3. `DamageSystem` 计算最终伤害（考虑防御、Buff 加成、伤害类型抗性）。
4. 目标（敌人/玩家）扣减生命，触发受伤/死亡事件。
5. 若敌人死亡，调用 `IExperienceSource` 提供经验，`ScoreManager` 增加击杀数。
6. 经验满足升级条件 → 触发 `GameEvents.OnLevelUp`，弹出 Buff 或技能选择面板。

### 5.2 Buff 应用流程
1. 玩家升级时，`BuffSelector` 随机展示三个 `BuffData`。
2. 玩家选择一个 → `BuffManager.ApplyBuff(BuffData)`。
3. 创建对应的 `BuffEffect` 实例，调用 `Apply` 修改 `PlayerStats` 属性（如增加伤害百分比）。
4. 若 Buff 有持续时间，到期后调用 `Remove` 恢复属性。

### 5.3 状态（Status）处理流程
1. 技能或敌人攻击施加状态（如中毒），调用 `StatusManager.AddStatus(StatusData)`。
2. 每个 Status 内部维护计时器，按 `interval` 执行 `StatusEffect.OnTick`。
3. `OnTick` 实现伤害、治疗或其他效果，并更新 UI（伤害数字）。
4. 持续期满后自动移除。

## 6. 扩展性与设计模式

- **数据驱动模式**：`BuffEffect`、`SkillEffect`、`StatusEffect` 均通过 ScriptableObject 资产创建实例。
- **观察者模式**：`GameEvents` 作为全局事件总线，模块间弱依赖。
- **接口隔离**：`IDamageable`、`IExperienceReceiver`、`IPassiveEffect` 保证系统间松耦合。
- **单例模式**：`MonoSingleton<T>` 基类确保 Manager 全局唯一。
- **对象池**：`BulletPoolManager` 减少子弹实例化开销，提升性能。

---

## 7. 网络架构要点

- 使用 **Netcode for GameObjects** 进行状态同步（`NetworkVariable`）。
- 客户端拥有 `ClientNetworkTransform` 来同步位置，服务器验证关键逻辑（如伤害计算、经验分配）。
- `SteamManager` 处理大厅、邀请等社交功能。
- UI 中 `NetworkUI` 显示房间信息。
- **注意**：当前未实现主机迁移，Host 退出后游戏会断开。

---

## 8. 性能优化考量

- **对象池**：子弹、伤害数字等频繁创建的对象。
- **资源按需加载**：关卡数据只在进入关卡时加载，Buff/技能数据在运行时按需引用。
- **网络压缩**：对于非关键数据（如动画参数）使用 `ClientNetworkAnimator` 减少带宽。
- **未来可考虑**：LOD 或剔除远距离敌人。

---

## 9. 待改进/潜在风险

- **代码耦合度**：部分 Manager 直接引用其他模块（如 `PlayerStats` 依赖 `BuffManager`），可进一步通过事件解耦。
- **存档完整性**：`SaveManager` 需要确保网络模式下主机存档的一致性。
- **敌人 AI**：当前是状态机（`EnemyState`），未来可扩展为行为树。
- **状态同步**：Buff 和状态在多人游戏中的同步需注意网络权限（服务器权威或客户端预测）。

---

## 10. 总结

本项目采用**数据驱动** + **模块化**的设计，结合 ScriptableObject 构建了灵活的战斗、技能、Buff 体系，并已具备多人联机基础。代码结构清晰，易于扩展新的敌人类型、技能或 Buff 效果。后续可进一步优化网络同步和 AI 行为，提升游戏整体品质。
